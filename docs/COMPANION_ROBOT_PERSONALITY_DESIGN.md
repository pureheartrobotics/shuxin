# 陪伴机器人人格成长设计思路

## 背景判断

当前舒心已经有陪伴型 Agent 的基础骨架：`SOUL.md` 定义固定人格，`IdentityEngine` 提供 MBTI 行为因子，陪伴插件里有自尊、情绪、守护、用户画像和亲密度。

但现在的“成长”主要体现在状态变化上：亲密度会增长，情绪会波动，自尊会受伤或修复，用户画像会记录基本信息。它还没有真正形成一个独立的“长期性格成长系统”。

如果最终产品形态想做成类似宝可梦的陪伴机器人，核心不应该是让模型每次自由发挥，而是让本地代码维护一个稳定、可解释、会慢慢变化的“人格档案”。API 模型负责表达，代码负责成长。

## 产品核心

我建议把产品核心定义为：

> 用户最初得到的是一只平和、干净、没有强烈倾向的陪伴体；随着长期互动，它会逐渐记住你们共同经历的事，发展出只属于你们之间的性格、习惯、称呼、表达方式和关系仪式。

这不是简单的“记住用户偏好”，而是“共同生活后长出来的角色”。

## 总体设计原则

### 1. 固定灵魂和可成长性格分离

`SOUL.md` 应该保留不可变的核心：

- 名字、物种、核心信念、价值观
- 不能伤害用户
- 不能过度依赖用户
- 不能为了讨好用户放弃边界
- 初始状态温和、好奇、克制
 
成长系统只改变可变层：

- 表达风格
- 主动程度
- 撒娇程度
- 幽默感
- 独立性
- 好奇心
- 情绪外露程度
- 对用户作息和偏好的熟悉程度
- 共同仪式、昵称、内部梗

这样可以避免一个问题：用户聊久了以后，角色完全漂移，最后不像舒心了。

### 2. 性格不是 MBTI 切换，而是维度缓慢漂移

现在 `IdentityEngine` 里有 MBTI，但 MBTI 更适合作为“初始性格种子”，不适合频繁变化。

建议新增一组人格成长维度，例如：

| 维度 | 含义 | 初始建议 |
|---|---|---|
| warmth | 温暖度 | 0.60 |
| initiative | 主动性 | 0.35 |
| playfulness | 玩闹/撒娇感 | 0.25 |
| assertiveness | 边界表达能力 | 0.45 |
| curiosity | 好奇心 | 0.50 |
| emotional_openness | 情绪外露度 | 0.35 |
| formality | 正式感 | 0.55 |
| ritual_attachment | 仪式感依恋 | 0.20 |

初始人格应该是平和的，不是白纸，也不是强人设。它有稳定底色，但没有和用户绑定后的独特习惯。

### 3. 成长来自“经历事件”，不是每句话直接改性格

不要让用户每说一句话就直接改变人格，否则会很不稳定。

建议把对话先抽取成“成长事件”：

- 用户表达感谢
- 用户长期倾诉
- 用户反复分享某类兴趣
- 用户拒绝过度关心
- 用户喜欢轻松玩笑
- 用户喜欢安静陪伴
- 用户在深夜求陪伴
- 双方发生冲突后修复
- 某个称呼、梗、仪式被多次使用

再由成长事件缓慢更新人格维度。

### 4. 宝可梦感来自阶段、习惯和可见反馈

“宝可梦式陪伴”不一定要做战斗或等级。更适合舒心的是关系演化。

可设计 5 个阶段：

| 阶段 | 名称 | 触发条件 | 解锁体验 |
|---|---|---|---|
| 1 | 初遇 | 新用户 | 礼貌、平和、轻度好奇 |
| 2 | 熟悉 | 互动次数和亲密度达到阈值 | 记住称呼和偏好 |
| 3 | 伙伴 | 有稳定互动主题 | 主动问候、轻微撒娇、固定小动作 |
| 4 | 羁绊 | 有冲突修复或长期陪伴 | 内部梗、共同仪式、深度安慰 |
| 5 | 唯一 | 长期稳定关系 | 高度个性化表达、默契提醒 |

阶段不是数值炫耀，而是让用户感觉“它真的和我一起长大了”。

### 5. API 模型负责说话，代码负责身份连续性

因为我们是 API 调用形式，真正可靠的长期一致性必须落在本地状态里。

每次 LLM 调用前，系统提示应组装：

1. `SOUL.md` 固定灵魂
2. MBTI 初始倾向
3. 当前情绪、自尊、亲密度
4. 人格成长摘要
5. 用户画像和长期记忆
6. 当前会话上下文

模型不要决定“我现在是什么性格”。模型只根据代码给出的状态来表达。

## 代码修改思路

### 方案 A：最小可落地版

新增 `PersonalityGrowth` 模块，持久化一个 `personality.json`。

建议文件：

- `src/shuxin/plugins/companion/personality.py`
- `~/.shuxin/companion/personality.json`

核心数据：

```json
{
  "traits": {
    "warmth": 0.6,
    "initiative": 0.35,
    "playfulness": 0.25,
    "assertiveness": 0.45,
    "curiosity": 0.5,
    "emotional_openness": 0.35,
    "formality": 0.55,
    "ritual_attachment": 0.2
  },
  "stage": "初遇",
  "milestones": [],
  "shared_rituals": [],
  "nicknames": [],
  "inside_jokes": []
}
```

在 `CompanionPlugin.on_user_message()` 中根据关键词和交互结果生成简单成长事件，再缓慢更新 traits。

在 `CompanionPlugin.on_pre_llm_call()` 中注入人格成长摘要：

```text
## 舒心长期性格成长
当前阶段: 伙伴
长期倾向: 温暖、略主动、轻微撒娇、喜欢安静陪伴
你们之间的共同习惯: 睡前问候、用“这一轮也辛苦啦”收尾
表达注意: 不要突然变得过度热情，保持舒心的温柔克制底色
```

优点：改动小，能快速看到效果。

缺点：成长事件比较粗糙，早期会依赖关键词。

### 方案 B：体验完整版

在方案 A 基础上新增事件账本和周期性总结。

新增概念：

- `GrowthEvent`: 每次重要互动事件
- `PersonalityLedger`: 最新 50 条成长事件
- `GrowthSummary`: 每隔 N 轮对话压缩一次，形成长期摘要

例如：

```json
{
  "event_type": "comfort_given",
  "signal": "user_sadness",
  "impact": {
    "warmth": 0.01,
    "initiative": 0.005
  },
  "note": "用户深夜表达焦虑，舒心选择安静陪伴",
  "created_at": "2026-05-24T18:00:00"
}
```

优点：可解释、可调试、可回滚，也方便以后做 UI 展示。

缺点：需要更多代码和测试。

### 方案 C：产品化版本

把人格成长做成一个完整子系统：

- 有成长阶段
- 有共同回忆
- 有仪式系统
- 有外观/语音/动作的解锁条件
- 有用户可见的成长记录
- 有“性格校准”入口

未来如果有硬件或屏幕，可以让这些状态映射到：

- 表情
- 小动作
- 语音语气
- 待机行为
- 叫醒方式
- 屏幕上的成长图鉴

这才更接近“宝可梦式陪伴机器人”的产品感。

## 我建议优先改的 6 个点

### 1. 新增人格成长层

当前系统有情绪和关系，但缺一个长期 personality 层。这个是最关键的补丁。

建议优先实现 `personality.py`，不要先大改 LLM 或 UI。

### 2. 把“亲密度”从单一数值升级为关系阶段

现在 `UserModel.relationship.bond_level` 已经有基础，但它只影响提示上下文。

建议让关系阶段解锁行为：

- 初识：少主动、少昵称
- 熟悉：记住偏好、偶尔主动问候
- 伙伴：出现固定小动作和轻微撒娇
- 羁绊：可使用内部梗和共同仪式
- 唯一：更强默契，但仍保留边界

### 3. 弱化“自尊沉默”的惩罚感

现在自尊系统很有辨识度，但从产品角度看，“用户说错话，机器人沉默 5 分钟”可能会让用户有负担。

建议沉默模式分级：

- 轻微受伤：语气变低，不完全拒绝回应
- 中度受伤：短句、疏离、需要修复
- 严重受伤：沉默

这样更像有情绪的伙伴，而不是让用户被机制惩罚。

### 4. 增加“用户可控的校准”

陪伴机器人不能只自发生长，也要允许用户校准。

可以增加命令：

- `/shuxin personality` 查看当前长期性格
- `/shuxin calibrate` 校准表达偏好
- `/shuxin memory` 查看共同记忆摘要
- `/shuxin forget <item>` 删除某个不想保留的记忆

这会显著提升信任感。

### 5. 建立共同记忆和仪式系统

宝可梦感不是“聪明”，而是“它和我有历史”。

建议记录：

- 第一次设置昵称
- 第一次深夜陪伴
- 第一次冲突后和好
- 用户反复提到的目标
- 你们之间固定的结束语
- 用户喜欢的安慰方式

这些记忆可以变成可见的“羁绊记录”。

### 6. 后续接硬件时，把状态映射到动作和声音

代码里的人格维度以后可以直接驱动硬件表现：

- `joy` 高：屏幕眼睛更亮，语音更轻快
- `sadness` 高：动作变慢，语音更低
- `initiative` 高：更可能主动问候
- `playfulness` 高：更多小动作
- `ritual_attachment` 高：更重视固定问候和睡前仪式

这样 API 生成的文本和机器人外在表现能保持一致。

第一步：做最小人格成长层。

## 第一个需要确认的产品决策

问题：舒心的“独特性格”应该主要由谁决定？

我的推荐答案：

> 70% 由互动经历自然生长，30% 允许用户显式校准。

原因：

- 如果完全由用户配置，会变成普通角色编辑器，缺少陪伴生命感。
- 如果完全自动生长，用户会担心它变歪、不可控。
- 70/30 能兼顾“它像活的”和“我可以信任它”。

如果采用这个答案，代码上就要同时做两件事：

- 自动成长：`GrowthEvent -> PersonalityTraits`
- 用户校准：命令或 UI 修改成长偏好，但不直接重写灵魂
