## 1. 产品是什么

互联网时代人们拥有私人电脑和手机：入口在自己手里，关系、照片、习惯围着「我的这台东西」转。计算可以在别处，**家在这台设备上**。

初心要对齐的是这个位置，而不是 Alexa 式租来的云音箱，也不是 PC 上 Hermes 那种写代码、刷网页、点桌面的数字员工。

| 不是 | 是 |
|------|------|
| 云端聊天窗口外挂一个底盘 | 家里这口会动、会看、会记得这家人的私人智能体 |
| 把 Hermes 全套工具搬上车 | Agent 当系统、生活技能当应用 |
| 所有生活需求第一年做完 | 先做「在家、围着这家人」的刚需，再扩技能 |

手机没有消灭电脑。第一年也不宣称「替代手机上的一切」，切口是：**在家开口就能办事**；认主人、认家人像小狗一样慢慢长，是关系层，不是第一卖点。

---

## 2. 原则

1. **家在车上。** 人格、这台车是谁、相册、备忘、绑定关系，用户能感知为「这台车的」。服务端可以同步备份，但不能是唯一副本且用户不可见、不可删。
2. **云是水电。** 听、想、说可以出域；用完尽量不沉淀。没有授权不拿对话训模型、不给其他用户。
3. **技能是生活，不是 IDE。** 不把终端、改仓库、桌面控制做成卖点。
4. **身体是差异。** 走过来、点头摇头、看一眼、拍一张，是手机和音箱做不到的。
5. **出域可解释。** 用户能理解「刚才出去了什么」；敏感类（照片、精确位置、录音原文）默认最小出域。
6. **办事是主菜，认人是小狗。** MBTI、钩子、家谱都要，但排在天气、问答、搜索、购物、身体动作之后。没有办事能力，性格是空壳。

## 3. 功能模块（按用户感知）

Agent 循环（当前 Hermes）负责选技能、调身体工具、再开口。人格仍来自 SOUL.md + MBTI 盲盒，陪伴钩子保留，自尊默认关。

### M5 生活技能 — 主路径是办事

像刚领回家的小狗：先不会认人，后来知道主人，再知道家里其他人，跟主人最亲。家谱技能按这个做。  
**但小狗首先得能陪你过日子。** 问答、天气、查信息、买东西、点外卖，排在性格和家谱前面。

| 技能 | 状态 | 用户说法 | 怎么落地（不要幻想 Hermes 自带中国生活 API） |
|------|------|----------|-----------------------------------------------|
| 解答问题 | 已有 | 「为什么天是蓝的」 | 大模型本身；不额外工具 |
| 天气出门 | 已有雏形 | 「明天带伞吗」 | 已有天气/地图路径，语音要稳定调通 |
| 提醒 / 备忘 | 已有雏形 | 「十分钟叫我」 | 车上+服务计时 |
| 网上搜信息 | 未开 | 「帮我查一下附近有没有儿科」 | **Hermes 有** `web_search` / 抽网页 / 浏览器；车上现已关掉。打开后是「查完口述+上屏」，不是给用户一个浏览器 |
| 买东西 | 部分 | 「买一包尿垫」「我想买那个配件」 | **自有商城已有**（小程序+微信收款）。淘宝/京东全网买：Hermes 只能在云端点网页，登录和支付过不了语音车，第一年不承诺 |
| 点外卖 | 无 | 「点一份番茄炒蛋盖饭」 | Hermes **没有**美团/饿了么接口，只有浏览器点网页。正路是开放平台或：车帮你问清楚 → 小程序/手机里下单支付 |
| 看 / 拍 / 走 / 头 | 已有 | 「过来」「摇头」 | 设备工具，继续做稳 |
| 家谱（认人） | 未做 | 「这是妈妈」 | 锦上添花；介绍写入家谱，不辨声纹 |
| 打电话 | 部分 | 「给妈妈打」 | RTC；依赖家谱里的称呼 |

### M5b Hermes 实际到哪一步（对用户诚实）

PC 上的 Hermes 很强的是：**搜网页、开浏览器点按钮、改文件、跑命令、定时任务、生图。**  
它**不是**美团、淘宝、微信支付。那些要官方接口或让用户在微信里付完。

车上若打开 Hermes 的搜索/浏览器，得到的是「云端查完告诉你」，不是「它有一个手机号能登录你的美团」。购物主路径继续走**你们自己的商城**；全网买和外卖是合作或「问清需求 → 手机确认支付」，不要写进今年必做。

### M6 听见与开口（语音管道）

当前：腾讯实时 ASR → Agent → 火山复刻 TTS。这是管道，不是产品卖点。产品卖点是这台车的声音稳定、像「它」在说话（复刻音色 + MBTI 语气）。

多模态端到端（Omni / Realtime）作为**可选技术路线**，见第 6 节，不在本期替换承诺里。

### M7 隐私与数据控制（必须做成功能，不是文案）

| 能力 | 状态 | 说明 |
|------|------|------|
| 音频短 TTL | 已有 | 默认约 12h 删磁盘 wav/mp3 |
| 对话文字保留策略 | 待定 | 须产品拍板：多久、能否关 |
| 一键清除云端记忆 | 年内 | 小程序；清完车还在，只是不记得了 |
| 「刚才出去了什么」 | 年内 | 本轮是否出了声音/照片/位置 |
| 相册默认不出域 | 已有倾向 | 仅「看一下」才上传认图 |
| 导出我的数据 | 以后 | 合规与「家在车上」配套 |

### M8 出厂、额度、运维

绑定、盲盒、工厂验收、分钟额度、Admin，保持现有路径。不在此展开。实验室 USB 转发是开发约束，不是用户体验。

## 4. 第一年范围（建议）

**做透（主菜：能办事）**

- 问答稳、天气稳、提醒/备忘稳  
- 身体：走、头、看、拍  
- 语音搜信息（打开 Hermes `web`，结果上屏+口述）  
- 小程序商城买你们卖的东西  
- 隐私：原文 30 天、忘记聊天 / 忘记我们  

**锦上添花（小狗认人，不挡办事）**

- 家谱介绍家人；MBTI/钩子保持现状；不做声纹  

**明确不做**

- 车上终端 / 写代码 / 冒充已登录美团淘宝  
- 自尊开关性格  
- 第一年全网代下单代付  

**以后**

- 外卖/全网购：官方接口或「车问清 → 手机支付」  
- 看家、IoT、生图、登记声音

## 5. 数据放哪（与定位对齐）

| 数据 | 现在实际 | 目标 |
|------|----------|------|
| 设备密钥、相册、车上备忘 | 车上 | 保持车上为权威；可选加密备份 |
| 用户/绑定/订单/额度 | 舒心 Postgres | 账号层，允许在云 |
| 对话原文、中期摘要、facts | 舒心服务 / Mem0 | 可关、可删、有期限；长期只留用户同意的 facts |
| 录音文件 | 服务磁盘短 TTL | 维持短 TTL；文字策略单独拍 |
| 识别 / 合成 / 推理 | 腾讯、火山、模型商 | 水电；合同与隐私政策写明不用于训共享模型（按供应商能力能争则争） |

实验室 Docker 在开发机上，**不是**用户的私有电脑。量产「家在车上」要靠车上副本 + 可删云端，而不是把服务器假装成本地。

## 6. 语音管道：专用 ASR/TTS vs 多模态大模型（待决）

结论先说：**现在不要单用一个多模态模型替换腾讯识别 + 火山复刻。** 可以并行评估，不能当已定方案。

### 6.1 听说已经能「一个模型又听又说」？

能。阿里 Qwen-Omni / Audio Realtime、OpenAI Realtime 等可以音频进、音频出，部分还带 function calling。这叫端到端语音，不是神话。

### 6.2 是不是更准？

不一定，而且「准」要拆开：

- **听清（ASR）**：吵家、远场、方言、叠音，专用识别（腾讯、讯飞，以及 Qwen3-ASR 这种**专门 ASR**）仍然更稳。Omni 的优势在「连着语气理解」，不是稳赢远场听写。  
- **说得像这台车（TTS）**：你们卖的是火山**复刻音色** + MBTI 语气。Omni 自带一套通用/情感声线，**不等于**已经克隆好的「这一台初心」。换掉火山，品牌声音要重新做。  
- **像在对话**：端到端少一次「先转成字再念」，语气、抢话、情绪更连。这是体感，不是字准确率。

### 6.3 和现在架构冲不冲

现在是：听成字 → Hermes 选技能/调手脚 → 再合成。记忆、工具、字幕、打断，都挂在**正文**上。

端到端若绕过文字：工具循环、中期摘要、用户可删的对话记录都会变难。部分 Omni 支持一边说话一边 function call，等于**重做语音主链路**，不是换两个 API。

隐私上：Omni 依然把声音送到阿里或 OpenAI，**不是更本地**。

### 6.4 建议

| 阶段 | 做法 |
|------|------|
| 现在 | 保持腾讯 ASR + Hermes + 火山复刻；远场用真车麦验收 |
| 评估 | 实验室加一条 Qwen-Omni Realtime 旁路，比：听清、首字/首声延迟、能否稳定调 `robot_head`/`robot_drive`、音色像不像这台车 |
| 以后 | 若 Omni 听清且工具稳，可作「通话体感」档；复刻声线仍可能独立；或 ASR 改 Qwen3-ASR、TTS 仍火山 |

决策标准（须真车，不凭 demo）：远场中文听清、工具不丢、音色可识别为这台车、成本与配额可接受。

## 7. 已对齐讨论（建议拍板，未当合同）

### 7.1 「文字」是什么、留多久

三层不要混：

| 名字 | 是什么 | 建议 |
|------|--------|------|
| 录音 | 磁盘上的 wav/mp3 | 已有约 12 小时删除。保持。 |
| **对话文字** | 每一轮「你说了啥、它回了啥」的字（`conversation_events`） | **默认 30 天自动删。** 不是记忆本体，主要给排障和短期连贯。 |
| 近况摘要 | 大约 7 天的 rolling_summary | 保持滚动覆盖，过期主题自然淡掉。 |
| 长期记得的 | 主人同意过的 facts：怎么称呼、过敏、家人是谁 | **一直留到用户删。** 这才是「它记得我们」。 |

用户问「你们存了我的聊天吗」：录音很快没；原文一个月没；「你叫小周、妈妈怕辣」可以一直在，直到清除。

**不要每年强制格式化。** 自动过期的是原文流水，不是把家忘掉。

### 7.2 家里几个人、能不能认出谁在说话

第一年 **认不出声纹是谁**。远场一个麦、客厅里几个人，声纹能做实验室，当卖点会经常认错（认错妈妈比不认更糟）。

建议产品规则：

1. **一家一车，一个主人。** 微信绑定者是主人，额度、清除、介绍家人只有主人能做。  
2. **家谱靠介绍，不靠偷听辨人。** 主人说「这是妈妈」「这是爸爸」「这是姥姥」「这是小狗豆豆」，写成家谱 facts。它知道家里有这些人，不等于此刻喇叭前面就是妈妈。  
3. **开口默认当「家里人在说话」。** 用家的记忆，不假装「你好妈妈」。除非对方自己说「我是妈妈」，或以后做了登记。  
4. **以后可选「登记声音」（2～4 人）。** 主人带着本人说一句固定话录入。未登记的客人只用家的公共记忆，不给私人备忘。认错则宁可不叫名字。

记忆怎么切：

| 层 | 谁用 |
|----|------|
| 家的记忆 | 家谱、公共备忘、一起做过的事。家里谁喊都用。 |
| 主人私密 | 只有主人（或已登记且确认是本人）才注入。第一年可先不做细切，只做家谱。 |
| 每人一份平行人生 | 第一年不做。一台车不是四个手机。 |

做不到声纹时：**介绍家人仍然有价值**——问「妈妈喜欢什么」答得上来；做不到的是你一开口它就叫对角色。产品文案不要写「能认出全家人」，写「主人介绍过的家人，它会记住」。

### 7.3 一键删除是什么（不是每年删一遍）

是 **用户想起来就按** 的控制，不是年审。搬家、送人、吵架、不放心时用。

建议两个按钮，不要合成一个「删除」：

| 按钮 | 清掉 | 留下 |
|------|------|------|
| **忘记聊天** | 对话文字、近况摘要、近期话题 | 家谱、主人名字、MBTI、账号、订单、相册 |
| **忘记我们** | 上面全部 + facts + 陪伴亲密度/画像 + 家谱 | 账号、订单、这台车的盲盒人格（身体还是它） |
| **恢复出厂**（更重，可放进设置深处） | 忘记我们 + 车上相册/备忘；绑定策略另定 | 固件；盲盒是否重新封印要单独拍 |

**建议默认主路径是「忘记聊天」**；「忘记我们」要二次确认。不要做「每年自动忘记我们」。
